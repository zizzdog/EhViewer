# EhViewer 下载结构平铺与集中式缩略图管理改造计划

## 一、 需求目标

1. **下载根目录平铺**：漫画打包为 `[gid]-[标题].cbz` 直接存放于下载根目录，不保留画廊同名子目录。
2. **后处理原子移动**：下载与 `archiveTo()` 过程保持原生逻辑，在 `postArchive()` 阶段通过 `atomicMove` 移动并重命名至根目录，随后删除临时目录。
3. **缩略图内部缓存管理**：封面统一保存在应用内部缓存目录 `cacheDir/download_thumbs/[gid].[format]`，可被系统设置中的“清除缓存”一键释放，且绝不污染系统相册与下载目录。
4. **在线阅读降级**：本地 CBZ 文件被移除后，阅读器检测文件缺失自动降级为网络在线加载（`useEhPageLoader`），下载列表仍可借助缓存或网络正常展示缩略图。

---

## 二、 技术决策

| 项目 | 方案 | 依据 |
| :--- | :--- | :--- |
| **打包策略** | `postArchive` 阶段原子移动 | 原生打包逻辑完全不变，仅在完成后通过文件系统原子移动（Linux `rename` 系统调用）移至根目录，避免侵入 JNI 归档流程 |
| **文件名长度** | 复用 `FileUtils.sanitizeFilename` | 该方法强制截断文件名至 200 字节以内（UTF-8），加上 `.cbz` 扩展名后约 204 字节，满足 Linux 255 字节限制 |
| **缩略图路径** | `appCtx.cacheDir/download_thumbs` | 存放在应用内部缓存，可被安卓“清除缓存”功能随时清理，且彻底切断与 SAF 下载目录的耦合 |
| **SAF 权限安全** | `keepNoMediaFileStatus` 零侵入 | 严禁在路径变更时访问未生效的旧目录，保持原版只对当前参数路径做操作，防止权限撤销引发死锁 |
| **在线回退** | `DownloadInfo.archiveFile` 返回空 | 寻址优先匹配根目录平铺 CBZ，缺失时返回 `null`，自动触发 `ReaderScreen` 的在线加载逻辑 |

## 三、 修改文件清单

| 文件 | 修改内容 |
| :--- | :--- |
| `SpiderDen.kt` | `postArchive()` 中执行 CBZ 原子移动、抽取缩略图至 `cacheDir` 并删除临时目录；`exportAsCbz()` 优先读根目录 CBZ |
| `DownloadManager.kt` | 声明 `downloadThumbLocation` 指向 `cacheDir/download_thumbs`；`archiveFile` 优先寻址根目录平铺 CBZ；`deleteDownload` 同步清理根目录 CBZ 与缩略图 |
| `DownloadThumbInterceptor.kt` | 缩略图优先读 `downloadThumbLocation`，兼容旧目录迁移，未命中走网络并回写缓存 |
| `CommonOperations.kt` | `confirmRemoveDownloadRange` 同步清理平铺 CBZ 与缩略图；`keepNoMediaFileStatus` 保持原版纯净逻辑，规范 import 排序 |

## 四、 实施步骤

1. **基础设施**：在 `DownloadManager.kt` 中声明 `downloadThumbLocation`（指向 `appCtx.cacheDir / "download_thumbs"`），改造 `archiveFile` 寻址与删除清理逻辑；在 `CommonOperations.kt` 修正 import 排序并移除副作用。
2. **后处理移动**：在 `SpiderDen.kt` 的 `postArchive()` 中增加 `cbzFile moveTo targetCbz`、封面另存至 cacheDir 与临时文件夹删除。
3. **拦截器适配**：在 `DownloadThumbInterceptor.kt` 中将缩略图路径切换为 `downloadThumbLocation`，保留网络回写机制。

## 五、 关键技术点备忘

1. **文件名长度安全性**：`info.downloadDirname()` 内部调用 `FileUtils.sanitizeFilename`，强制截断至 200 字节（UTF-8），加上 `.cbz` 后共约 204 字节，满足 Linux 255 字节限制。
2. **后处理原子移动**：由于源文件与目标文件在同一挂载点，`atomicMove` 为内核级 `rename` 操作，耗时 <1ms，不产生二次 I/O。
3. **SAF 权限时序安全**：下载路径切换时，系统会先释放旧 URI 权限，因此任何方法在路径设置完成前不得访问旧 `downloadLocation`。
