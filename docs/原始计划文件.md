# EhViewer 下载结构平铺与集中式缩略图管理改造计划（全量基线规划文档）

## 一、 项目背景与改造目标

针对 EhViewer 进行轻量化专项定制改造，使其适配**高吞吐量漫画归档与云端转存**的个人使用习惯。

### 1. 用户核心痛点
* **漫画库规模庞大，本地存储告急**：手机空间受限，用户需要定期将下载的漫画压缩包批量转移至云端网盘或家庭 NAS 存储。
* **原版目录碎散冗余**：EhViewer 默认在下载根目录下为每部漫画新建独立的画廊同名子文件夹，内部混杂存放 `[gid].cbz`、`ComicInfo.xml` 以及 `thumb.jpg`。这导致批量迁移时层级极多，将文件上传云端并清理后，手机端还会留下成百上千个空文件夹与碎片元数据。
* **下载列表充当“半收藏列表”**：即使本地的漫画源文件被移至云端删除，用户依然希望下载列表界面整洁可用、封面缩略图不损坏，并且在点击阅读时能够自动、平滑地回退至网络在线阅读模式，无需重新搜索画廊。

### 2. 改造核心目标
1. **下载根目录极简平铺**：下载根目录下没有任何画廊同名子文件夹，所有已完成的漫画直接以 `[gid]-[标题].cbz` 的格式平铺存放在下载根目录下。
2. **下载与打包过程“零侵入”**：下载阶段与 JNI 底层打包过程完全保持原生逻辑不动。只在下载完成后的**后处理钩子 (`postArchive`)** 中执行原子级的重命名与移动操作，实现极速执行与最小代码修改面。
3. **缩略图集中存放与独立防相册扫描**：将分散的缩略图抽离至下载根目录下的单一专属文件夹 `thumb/` 中（命名为 `[gid].[ext]`），并在其中常驻内置 `.nomedia` 文件，阻断系统相册扫描。
4. **云端转存友好与在线阅读自动降级**：当用户将根目录下的 `.cbz` 文件移走删除后，下载列表通过 `thumb/` 正常显示封面；点击进入阅读器时，底层自动检测本地文件缺失并无缝降级为在线加载（`useEhPageLoader`），提供媲美在线收藏夹的流畅体验。

## 二、 关键技术方案选型与讨论决策结论

| 决策维度 | 选定方案 | 决策依据与深度原理 |
| :--- | :--- | :--- |
| **打包流程侵入性** | **后处理原子移动改名 (Zero-invasion Move)** | **放弃在打包期拦截路径的思路**。原版的下载写入与 `archive()` 底层 JNI 批处理打包保持 100% 原生不变（仍然在画廊子目录内生成 `[gid].cbz`）。仅在打包完成后的生命周期钩子 `postArchive()` 中，通过 `atomicMove` 将文件原子重命名移动到根目录。同分区移动仅耗时 <1ms，绝不重新读写数据块，最省电、最安全 |
| **Linux 255 字节限制**| **依托原生 FileUtils 200 字节截断** | Linux / Android ext4 和 F2FS 的文件名最大限制为 255 字节（UTF-8 编码）。EhViewer 底层 `FileUtils.sanitizeFilename` 已严格内建了 `MAX_FILENAME_BYTES = 200` 字节截断并剔除无效字符。因此 `[gid]-[Title].cbz` 最大仅占约 204 字节，严格杜绝 `ENAMETOOLONG` 错误 |
| **缩略图存储位置** | **下载根目录独立子目录 (`download/thumb/`)** | 将所有封面统一沉淀至 `downloadLocation / "thumb"`，脱离画廊同名文件夹。在打包后将原画廊文件夹整包删除，下载根目录只剩下平铺的 `.cbz` 文件和唯一的 `thumb/` 文件夹 |
| **.nomedia 放置策略** | **thumb 目录专属独立内置** | 虽然 Android 原生 MediaScanner 规则为“父目录放 `.nomedia` 会递归忽略子目录”，但当用户在 EhViewer 设置中开启“媒体扫描”时，根目录的 `.nomedia` 会被主动删除。在 `thumb/` 内部常驻一个独立的 `.nomedia`，能形成坚固的独立安全屏障，彻底阻断数千张缩略图污染手机相册 |
| **缩略图加载与回退** | **优先读统一目录，缺失时走网络并回写** | 改造 `DownloadThumbInterceptor`：优先读取 `thumb/[gid].[format]` 实现秒开；若文件丢失或被清理，自动放行走 Coil 网络请求，成功后自动回写沉淀至 `thumb/` 目录 |
| **在线阅读降级机制** | **原生 ReaderScreen Fallback 闭环** | 原版 `ReaderScreen.kt` 原生设计了“若 `archiveFile == null` 则切换为 `useEhPageLoader`”的优雅降级。只需让 `archiveFile` 优先寻址根目录平铺文件，本地无文件时自然返回 `null` 即可触发在线翻页 |
| **删除任务协同** | **平铺 CBZ 与专属缩略图同步清理** | 当用户在界面勾选“删除文件”时，同步清理根目录下平铺的 `[dirname].cbz` 与 `thumb/` 目录下的 `[gid].*`，确保无孤儿残留 |

## 四、 四阶段实施全流程

### 阶段一：下载管理与寻址基础设施改造 (Phase 1)
* 在 `DownloadManager.kt` 中声明 `val downloadThumbLocation: Path`（指向 `downloadLocation / "thumb"`），并在初始化时自动校验与创建内置 `.nomedia` 文件。
* 改造 `DownloadInfo.archiveFile`：
  1. 优先检查根目录平铺路径 `downloadLocation / "${dirname}.cbz"`；
  2. 若不存在，向下兼容检查旧版画廊文件夹 `downloadDir / "$gid.cbz"`。
* 改造 `DownloadManager.deleteDownload` 与 `CommonOperations.confirmRemoveDownloadRange`：支持在勾选删除时清理平铺 CBZ 文件与 `thumb/` 内的缩略图。

### 阶段二：下载后处理原子移动与目录清理 (Phase 2)
* 严格保持 `SpiderDen.archive()` 与 `archiveTo()` 100% 原版不动，保持下载期间在临时子目录下流式写入。
* 在 `SpiderDen.kt` 的后处理函数 `postArchive()` 中实现后处理逻辑：
  1. 检测到子目录下 `[gid].cbz` 生成完毕后，将其通过 `atomicMove` 原生移动并改名为 `downloadLocation / "${info.downloadDirname()}.cbz"`；
  2. 新增 `saveThumbToUnifiedLocation()`：将原画廊目录内的封面图或第 1 页安全拷贝至 `downloadThumbLocation / "${gid}.${format}"`；
  3. 确认移动与抽取成功后，执行 `dir.delete()`，将原画廊子文件夹彻底删除；
  4. 适配 `exportAsCbz()`，优先从根目录平铺的 CBZ 获取源文件。

### 阶段三：集中式缩略图加载与网络回退闭环 (Phase 3)
* 改造 `DownloadThumbInterceptor.kt`：
  1. 将缩略图查找源重定向为 `downloadThumbLocation / "${info.gid}.${format}"`；
  2. 兼容兜底：若统一目录未命中但旧版子目录存在，自动将旧封面迁移至统一目录；
  3. 网络回退：若本地完全无文件，放行请求走 Coil 远程加载，加载成功后将缩略图沉淀写入 `downloadThumbLocation`。

### 阶段四：验证、文档追踪与编译准备 (Phase 4)
* 验证 Linux 255 字节文件名截断机制的边界鲁棒性。
* 验证转存云端场景（手动移除根目录 `.cbz` 文件）：验证下载列表封面依然完整秒开、点击漫画无缝平滑进入在线阅读模式。
* 同步完善 `docs/当前开发进展.md`，并在确认无误后提供免本地环境的 GitHub Actions 编译指南。
