# EhViewer 下载结构平铺与集中式缩略图管理改造计划

## 一、 需求目标

1. **下载根目录平铺**：漫画打包为 `[gid]-[标题].cbz` 直接存放于下载根目录，不保留画廊同名子目录。
2. **下载临时文件与就地直出**：下载期间单页散装图片直接存放在用户设定的下载目录下（`downloadLocation/[gid]-[Title]`），不占用应用内部私有存储；打包时由 JNI 直接向外层根目录创建并写入 `[gid]-[Title].cbz`，打包完成后彻底清理画廊临时子目录。
3. **缩略图内部缓存管理**：封面统一保存在应用内部缓存目录 `cacheDir/download_thumbs/[gid].[format]`，可被系统设置中的“清除缓存”一键释放，且绝不污染系统相册与下载目录。
4. **在线阅读降级**：本地 CBZ 文件被移除后，阅读器检测文件缺失自动降级为网络在线加载（`useEhPageLoader`），下载列表仍可借助缓存或网络正常展示缩略图。
5. **规范化 ComicInfo.xml 写入系统（适配 LANraragi 后端与中文标签翻译）**：
   - 彻底修复 EhViewer 原生缺少 `<Title>`、微标签全塞入 `<Genre>` 导致媒体库分类污染、`<Teams>` 乱挂载等严重缺陷。
   - 严格适配 LANraragi 官方 `ComicInfo.pm` 插件的标签提取规则。
   - 支持联动“显示标签翻译”设置：开启时输出翻译后的命名空间与标签名（如 `女性:女仆`、`<Penciller>森仓圆</Penciller>`），关闭时输出原始英文。

## 二、 技术决策

| 项目 | 方案 | 依据 |
| :--- | :--- | :--- |
| **临时下载目录** | 用户设定的 `downloadLocation / dirname` | 确保大体积漫画下载期间的全部 I/O 和存储都落在外部下载目录中，不占用内部存储 |
| **打包策略** | `archive()` 直出根目录 CBZ | Android SAF 体系下 `renameDocument` 仅支持同级重命名，无法跨目录移动；直接在根目录调用 `createDocument` 创建 CBZ 文件最为稳妥可靠 |
| **文件名长度** | 复用 `FileUtils.sanitizeFilename` | 该方法强制截断文件名至 200 字节以内（UTF-8），加上 `.cbz` 扩展名后约 204 字节，满足 Linux 255 字节限制 |
| **缩略图路径** | `appCtx.cacheDir/download_thumbs` | 存放在应用内部缓存，可被安卓“清除缓存”功能随时清理，且彻底切断与 SAF 下载目录的耦合 |
| **SAF 权限安全** | `keepNoMediaFileStatus` 零侵入 | 严禁在路径变更时访问未生效的旧目录，保持原版只对当前参数路径做操作，防止权限撤销引发死锁 |
| **在线回退** | `DownloadInfo.archiveFile` 返回空 | 寻址优先匹配根目录平铺 CBZ，缺失时返回 `null`，自动触发 `ReaderScreen` 的在线加载逻辑 |
| **ComicInfo 格式** | 适配 LANraragi 规则的标准 XML | 补齐 `<Title>`，`<Genre>` 仅放大分类，`<Tags>` 放带命名空间微标签，`<Teams>` 留空 |
| **标签翻译顺序** | **先英文分类提取，后内容按需翻译** | 若先翻译，`artist` 变成中文“艺术家/作者”，将导致无法匹配字段；必须先用 raw 英文命名空间将画师/社团/角色/微标签分流，再对提取出的值和命名空间进行中文翻译 |

## 三、 ComicInfo.xml 映射规范与翻译时序设计

### 1. LANraragi `ComicInfo.pm` 映射矩阵

依据 LANraragi 官方 `ComicInfo.pm` 插件对各节点的处理规则，精准映射如下：

| XML 节点 | 取值来源（未开启翻译） | 取值来源（开启翻译） | LANraragi 解析结果 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **`<Title>`** | `title` | `title` | 漫画标题 `$title` | **必须补齐**，否则 LRR 丢失标题并被迫回退文件名 |
| **`<Series>`** | 留空（或多话纯系列名） | 留空（或多话纯系列名） | `series: [系列名]` | 避免将画廊长标题写入导致 LRR 产生大量冗余 series 标签 |
| **`<AlternateSeries>`** | `titleJpn` | `titleJpn` | 外部阅读器展示 | 遵循标准 |
| **`<Writer>`** | 社团纯名称列表（逗号分隔） | 翻译后的社团名称列表 | **`group: [社团名]`** | LRR 会自动向 `<Writer>` 追加 `group:` 前缀 |
| **`<Penciller>`** | 画师纯名称列表（逗号分隔） | 翻译后的画师名称列表 | **`artist: [画师名]`** | LRR 会自动向 `<Penciller>` 追加 `artist:` 前缀 |
| **`<Characters>`** | 角色纯名称列表（逗号分隔） | 翻译后的角色名称列表 | **`character: [角色名]`** | LRR 会自动向 `<Characters>` 追加 `character:` 前缀 |
| **`<LanguageISO>`** | `simpleLanguage?.lowercase()` | 语言代码或原语言名 | **`language: [语言]`** | LRR 会自动向 `<LanguageISO>` 追加 `language:` 前缀 |
| **`<Web>`** | 画廊详情页 URL | 画廊详情页 URL | **`source: https://e-hentai.org/g/...`** | LRR 会自动向 `<Web>` 追加 `source:` 前缀 |
| **`<Genre>`** | 画廊大分类 `category`（如 `Doujinshi`） | 翻译后大分类（如 `同人志`） | **`Doujinshi`** 或 **`同人志`** | LRR 直接作为分类标签入库，Komga 流派分类保持纯净 |
| **`<Tags>`** | 微标签集：`parody:xxx, female:xxx, male:xxx, other:xxx` | 翻译微标签集：`原作:xxx, 女性:女仆, 男性:xxx` | **直通原样入库** | LRR 会按逗号拆分原样加入 tags，命名空间完整保留！ |
| **`<Teams>`** | **保持留空** | **保持留空** | - | 彻底废除 EhViewer 原版将原作塞进超级英雄战队的错误逻辑 |
| **`<PageCount>`** | `pages` | `pages` | 用于页数记录 | 遵循标准 |
| **`<CommunityRating>`** | `rating` | `rating` | 用于评分展示 | 遵循标准 |
| **`<Manga>`** | `YesAndRightToLeft` | `YesAndRightToLeft` | 兼容第三方阅读器自动右翻 | 体验加分项 |

### 2. 标签翻译处理的严格时序保证

为避免“因提前翻译导致英文命名空间丢失，进而无法正确归集到对应 XML 节点”的致命逻辑漏洞，数据流必须遵循以下两阶段：

```text
               原始画廊标签池 (tagGroups 或 simpleTags)
                               │
                               ▼
        ┌──────────────────────────────────────────────┐
        │ 【第一步：原始英文命名空间分类归集 (Classification)】 │
        └──────────────────────┬───────────────────────┘
                               │ 基于原始英文 namespace 进行分类：
                               ├─ Artist / Cosplayer ──> rawArtists
                               ├─ Group ───────────────> rawGroups
                               ├─ Character ───────────> rawCharacters
                               ├─ Parody ──────────────> rawParodies
                               └─ Female/Male/Other 等 ─> rawOtherTags
                               │
                               ▼
        ┌──────────────────────────────────────────────┐
        │ 【第二步：条件化内容与命名空间翻译 (Translation)】    │
        └──────────────────────┬───────────────────────┘
                               │ 检查 Settings.showTagTranslations.value:
                               │
           ┌───────────────────┴───────────────────┐
           ▼                                       ▼
     【开启翻译模式】                         【未开启翻译模式】
   1. 画师名通过 EhTagDatabase 翻译         1. 画师名保留原始英文/罗马音
   2. 社团名通过 EhTagDatabase 翻译         2. 社团名保留原始英文/罗马音
   3. 角色名通过 EhTagDatabase 翻译         3. 角色名保留原始英文/罗马音
   4. 大分类映射为中文（如“同人志”）         4. 大分类保留英文（如“Doujinshi”）
   5. 微标签与命名空间同时中文化：            5. 微标签保留原始英文：
      前缀取中文 (female -> "女性")             前缀取英文 ("female")
      标签取中文 (maid -> "女仆")               标签取英文 ("maid")
      拼接为 "女性:女仆", "原作:舰队Collection"   拼接为 "female:maid", "parody:kantai collection"
                               │
                               ▼
        ┌──────────────────────────────────────────────┐
        │ 【第三步：注入并序列化为标准 ComicInfo.xml】        │
        └──────────────────────────────────────────────┘
```

## 四、 修改文件清单

| 文件 | 修改内容 |
| :--- | :--- |
| `SpiderDen.kt` | `imageDir` 固定为 `downloadDir`，临时图片存下载目录；`archive()` 直出根目录 CBZ；`postArchive()` 抽取缩略图至 cacheDir 并清理临时目录 |
| `DownloadManager.kt` | 声明 `downloadThumbLocation` 指向 `cacheDir/download_thumbs`；`archiveFile` 优先寻址根目录平铺 CBZ；`deleteDownload` 同步清理根目录 CBZ 与缩略图 |

| `ComicInfo.kt` | 重构 `ComicInfo` 数据结构与 `getComicInfo()` 生成函数，实现面向 LANraragi 的字段映射与双阶段标签翻译 |

## 五、 实施步骤

1. **基础设施**：在 `DownloadManager.kt` 中声明 `downloadThumbLocation`（指向 `appCtx.cacheDir / "download_thumbs"`），改造 `archiveFile` 寻址与删除清理逻辑；在 `CommonOperations.kt` 修正 import 排序并移除副作用。
2. **下载与打包直出**：在 `SpiderDen.kt` 中取消 `tempDownloadDir` 拦截，将单页图片直接写入 `downloadDir`；`archive()` 直接将 CBZ 输出至 `downloadLocation / "$dirname.cbz"`，`postArchive()` 负责封面抽取与临时目录删除。
3. **拦截器适配**：在 `DownloadThumbInterceptor.kt` 中将缩略图路径切换为 `downloadThumbLocation`，保留网络回写机制。
4. **ComicInfo.xml 重构**：在 `ComicInfo.kt` 中接入 LANraragi 映射规则，接入 `EhTagDatabase` 实现“先英文分类、再按需翻译”的标签中文化输出。

## 六、 关键技术点备忘

1. **文件名长度安全性**：`info.downloadDirname()` 内部调用 `FileUtils.sanitizeFilename`，强制截断至 200 字节（UTF-8），加上 `.cbz` 后共约 204 字节，满足 Linux 255 字节限制。
2. **SAF 跨目录限制规避**：Android SAF 的 `atomicMove` 本质为 `renameDocument`，不能实现跨级目录搬迁；改为在 `archive()` 打包时直接由 SAF 在根目录 `createDocument`，规避了移动失败导致的误删风险。
3. **SAF 权限时序安全**：下载路径切换时，系统会先释放旧 URI 权限，因此任何方法在路径设置完成前不得访问旧 `downloadLocation`。
4. **标签翻译顺序不可逆**：标签归集必须在未翻译状态下通过英文命名空间精准路由到 `rawArtists`、`rawGroups` 等容器中，绝不能在未分类前全局直接替换字符串，否则会导致 `<Penciller>` 等核心节点丢失数据。
